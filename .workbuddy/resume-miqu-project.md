## 一、完整项目条目（可直接粘贴）

### 觅取（Miqu）—— 前后端分离社交平台　　20XX.XX – 2025.12

**项目描述**：Spring Boot 3 + MyBatis-Plus + MySQL 后端（11 张表、50 个接口）+ Vue 3 前端，
完整覆盖注册登录、用户搜索、关注关系、动态、点赞评论、私信通知、后台管理闭环。
**独立完成前后端开发与测试体系搭建。**

**技术栈**：Java 21 · Spring Boot 3 · MyBatis-Plus · MySQL · JUnit 5 · MockMvc · Python · pytest · Requests · Allure · JWT

**核心工作**

- **双层自动化测试体系（490 条）**：JUnit 5 + MockMvc 289 条负责进程内分支覆盖（`@Transactional` 自动回滚，把业务规则钉死）；pytest + Requests 201 条打真实 HTTP + 真实 MySQL，负责端到端联调、序列化契约与过滤器链验证。两者互补而非重复——MockMvc 快且可回滚，pytest 能暴露"单元全绿、一联调就挂"的问题

- **用例幂等设计**：针对 pytest 真实落库、不可回滚的问题，确立两条纪律——断言只取操作前后的**差值**（`after == before + 1`），写数据只用**当次新建的随机用户**（项目无删除用户接口，固定用户名二次执行必撞唯一键）。改造后整套用例可连续重复执行，无需中途重置数据库

- **权限矩阵验证**：11 个后台接口 × 3 种身份（未登录 / 非管理员 / 管理员）断言 401 / 403 / 200，并专项断言 **401 与 403 文案必须不同**——前端才能区分该"引导登录"还是"提示无权限"

- **契约与一致性验证**：实体字段与表结构一致性测试；健康检查真实探测数据库（规避 Hikari 懒初始化导致的"健康检查 UP 但业务接口全 500"）；Long 型 id 序列化为字符串的序列化契约测试（防 JS Number 精度丢失）

- **缺陷沉淀为回归防线**：把开发中踩到的真实缺陷固化为用例——实体误标逻辑删除导致首次查询报表不存在、健康检查只报进程存活不报数据源状态等

- **覆盖诚实性**：对确实走不到的分支（种子数据仅 1 个管理员，禁用管理员账号的分支无法触达）明确记录为**覆盖缺口**并给出补齐方案，不用恒真断言伪造覆盖率

- **AI 测试平台实测**：用自研 AI 测试平台对其中 22 个接口做端到端实测——AI 从接口文档生成 68 条结构化用例，**接口覆盖率 100%、最终轮 100% 通过**；量化 AI 产出的可执行率（原样执行 90%，修正自创断言语法后 100%）、覆盖偏差与失败分析准确率（3/5），反向发现平台自身缺陷 7 项、接口文档与实现不一致 2 处
