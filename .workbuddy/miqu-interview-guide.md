# 第 1 部分 一分钟讲清楚这个项目

背下来，面试开场就用：

> Miqu 是一个前后端分离的中小型社交平台，后端 Spring Boot + MyBatis-Plus，前端 Vue 3，共 11 张表、38 个接口。
> 业务上完整覆盖"注册登录 → 用户搜索 → 关注关系 → 发布动态 → 点赞评论 → 私信通知 → 后台管理"的闭环。
> 我在这个项目里的重点是**测试**：搭了一套双层的自动化测试体系，JUnit + MockMvc 负责把业务规则钉死（289 条），pytest 打真实 HTTP 和真实数据库负责端到端和契约验证（201 条），一共 490 条。
> 设计上我特别在意两件事：一是**测试要能重复跑**，二是**接口契约要稳定到前端和测试都能依赖**。

# 第 2 部分 必须能答的 12 个问题

每题都标了**代码位置**——先自己去看一遍，再回来看答案要点。

### Q1. 统一响应为什么让 HTTP 状态恒为 200？
**位置**：`exception/GlobalExceptionHandler.java`

**要点**：业务结果放在响应体 `code` 里，HTTP 状态只表达"请求有没有到达应用"。好处是前端与自动化测试只需处理一套解析逻辑。**但要主动说出代价**：这偏离了 REST 语义，如果用网关/监控按 HTTP 状态做告警会失效。这是有意的取舍，不是没想过。

### Q2. 白名单"失败关闭"是什么意思？
**位置**：`security/AuthInterceptor.java`、`config/application.yml` 的 `miqu.auth.white-list`

**要点**：不在白名单里的 `/api/**` **一律要求登录**。新增接口如果忘了配置，默认是受保护的，而不是裸奔。这是"失败关闭"（fail-closed）而非"失败开放"（fail-open）。
**加分细节**：白名单用 `{id:[0-9]+}` 而不是 `*`，否则 `/api/users/me` 会被一并放行，个人中心变成免登录可访问。

### Q3. 禁用用户后，他手里的旧 Token 为什么立刻失效？
**位置**：`security/JwtAuthenticationFilter.java`

**要点**：JWT 无状态，光验签名是验不出状态的。所以过滤器解析 Token 后**必须查一次库**，校验账号是否被禁用、是否已被逻辑删除。不查库的话，"用户状态管理"这个功能等于没实现。
**这题的深水区**（大概率会追问）：
> **为什么失败不直接抛异常，而是塞进 `request.setAttribute`？**
> 因为过滤器**只做身份识别，不做访问控制**。放行还是拒绝，要由 `AuthInterceptor` 结合白名单来判。这样白名单接口（比如游客浏览动态）即使带着一个坏 Token 也能正常返回——否则一个过期 Token 会让游客连首页都打不开。
> **还有一个坑**：`CurrentUserHolder.clear()` 必须写在 `finally` 里。因为 `preHandle` 抛异常时 `afterCompletion` 不会执行，残留的 ThreadLocal 会让复用同一线程的下一个请求**继承上一个用户的身份**——这是越权漏洞。

### Q4. 哪些表用逻辑删除？哪些用物理删除？为什么？
**位置**：`entity/BaseEntity.java`（带 `@TableLogic`）vs `entity/BaseCreateEntity.java`（不带）

**要点**：
- **逻辑删除**：`user`、`post`、`comment` —— 这些是业务主表，需要保留痕迹
- **物理删除**：`follow`、`post_like`、`post_image` —— 这是**最关键的一题**

**为什么关系表不能逻辑删除**：`post_like` 上有唯一键 `uk_post_user`。如果取消点赞只做软删，那行数据还在，唯一键仍被占用，用户**永远无法再次点赞**——直接违反需求本身。同理 `follow`。
**这个答案的杀伤力在于**：它是走通业务之后才能发现的坑，不是背概念能答出来的。

### Q5. 点赞数是怎么更新的？
**位置**：`service/impl/PostServiceImpl.java`、对应的 `PostMapper`

**要点**：计数一律用**原子 UPDATE**（`like_count = like_count + 1`），禁止"查出来 +1 再写回"。
**为什么**：并发下后者会丢失更新（两个请求同时读到 10，各自写回 11，实际应该 12）。这是典型的"本地测试永远测不出来"的 bug。

### Q6. 怎么防止重复点赞？
**位置**：`exception/GlobalExceptionHandler.java` + `database/schema.sql` 的唯一键

**要点**：两道防线。
1. Service 层先查一次，已点赞就返回 409 —— 但**这只能挡住99%的情况**
2. 真正兜底的是**数据库唯一键**：并发下两个请求都通过了第 1 步检查，第二个 `INSERT` 会撞唯一键抛 `DuplicateKeyException`，全局异常处理器**按索引名**把它翻译成业务错误码（`uk_post_user` → 409「已点赞」）

**必须能说出**："这是并发下唯一正确的兜底，前面的查库检查只是为了返回更友好的文案。"
**连带知识点**：改索引名时要同步改 `GlobalExceptionHandler`，否则翻译会失效。

### Q7. 什么叫"测试幂等"？你是怎么做到的？
**位置**：`tests/conftest.py` 开头的 docstring + `fresh_user` 夹具

**要点**：pytest 打的是真实 HTTP、写的是真实数据库，**而且没有回滚**。所以如果断言写 `用户总数 == 21`，第二次跑就挂了。两条纪律：
1. **断言只取差值**：先读一次、操作、再读一次，断言 `after == before + 1`
2. **写数据只用当次新建的随机用户**：`fresh_user` 生成带 uuid 后缀的用户名——因为测试会真实创建用户，而且**项目没有删除用户的接口**，固定用户名第二次跑就撞唯一键

**结果**：整套用例可以连续跑两遍结果一致，中途不需要重置数据库。

### Q8. MockMvc 和 pytest 为什么要维护两套？
**位置**：`backend/src/test/**` vs `tests/**`

**要点**：不是重复，是**互补**：

| | JUnit + MockMvc | pytest |
|---|---|---|
| 运行 | 进程内，不起 HTTP | 真实 HTTP + 真实 MySQL |
| 事务 | `@Transactional` 自动回滚 | 真实提交，不回滚 |
| 速度 | 快 | 慢 |
| 擅长 | 规则密集的分支覆盖 | 端到端联调、序列化、过滤器链、契约验证 |

**核心论据**：MockMvc 快且能回滚，适合把业务规则钉死；pytest 慢但真实，能发现"**单元测试全绿、一联调就挂**"的问题——比如序列化格式不对、过滤器顺序错了、CORS 没配。这类问题在进程内测试里根本暴露不出来。

### Q9. 为什么有些断言只断错误码，不断文案？
**位置**：`test_auth.py` 里 `test_register_blank_username_only_checks_code` 的注释

**要点**：Bean Validation 对同一字段可能同时触发多条约束（空用户名会同时违反 `@NotBlank`、`@Size`、`@Pattern`），而**校验器不保证触发顺序**。所以：
- 能构造出"只违反一条约束"的输入 → 断言**精确文案**
- 无法避免多条同时命中 → 只断言**错误码**，并在用例里注明原因

**价值**：让测试既严格，又不会因为校验器内部顺序变化而变成假失败。这体现的是"想过为什么"，不是"随手写的"。

### Q10. 401 和 403 为什么必须是两套文案？
**位置**：`AdminAccessControlTest.forbiddenMessageDiffersFromUnauthorized`

**要点**：`/api/admin/**` 不在白名单里，所以**未登录会被拦成 401**；登录了但不是管理员，才由 `@RequireAdmin` 拦成 **403**。两者文案不同（"未登录或登录状态已失效" vs "无权限执行该操作"），前端才能判断该**引导登录**还是**提示无权限**。混成一个码，前端就只能干瞪眼。

### Q11. 健康检查为什么要探测数据库？
**位置**：`controller/HealthController.java` + `HealthControllerTest`

**要点**：这是踩过的真实坑。Hikari 连接池是**懒初始化**的——应用可以"启动成功"，然后每个业务请求都 500。如果健康检查只报进程存活，就会出现「健康检查 UP，但业务全挂」这种极具误导性的状态。所以 `/api/health` 会**实际打一次数据库**，并返回 `database: UP/DOWN`。

### Q12. 上传为什么按文件头魔数判断，而不是看后缀？
**位置**：`service/impl/LocalFileStorageService.java`

**要点**：后缀名是用户可以随便改的，把 `.sh` 改成 `.jpg` 就能绕过后缀校验。魔数是文件**内容**的前几个字节，改不了。实现上支持 JPEG / PNG / GIF / WebP 四种，另外还有两道保险：UUID 重命名（杜绝 `../../` 路径穿越）+ 写入前检查目标路径必须在上传根目录内。
**注意**：这个**功能有，但测试没有**——被问了就如实说，别硬编。

# 第 3 部分 深水区（用来分辨"真懂"和"背过"）

如果面试官想探你的深浅，大概率会问这些。答得上来说明你真读过代码。

1. **ThreadLocal 为什么必须在 `finally` 里清理？**
   → `preHandle` 抛异常时 `afterCompletion` 不执行，线程被复用时会继承上一个用户的身份，造成越权。

2. **为什么关系表不加 `deleted` 字段？**
   → 唯一键会被软删行占用，"取消点赞后无法再次点赞"。

3. **私信为什么不用 WebSocket？**
   → 需求明确"不要因为追求技术而导致项目复杂化"，采用 REST + 轮询（导航栏 15 秒、聊天页 3 秒）。这是个**克制**的答案，面试官通常吃这套。

4. **为什么用户表不支持注销，只用 status 禁用？**
   → 唯一的 `username`/`email` 与逻辑删除天然冲突（注销后用户名仍被占用，新用户无法注册同名）。

5. **为什么 `logout` 无法在服务端强制失效？**
   → JWT 无状态，退出只是客户端丢 Token，已签发的在 7 天内仍可用。要做真失效需要 Redis 黑名单或 access + refresh 双 Token。
   **对比着说**：但**禁用是立即生效的**，因为过滤器每请求查库。这两者行为不同，要说清楚。

6. **`id` 为什么要序列化成字符串？**
   → JS 的 Number 安全上限是 2^53，将来换雪花 ID 会静默丢精度。

7. **为什么不用物理外键？**
   → 逻辑删除与 `ON DELETE` 语义冲突；批量造数、清库、迁移都要按依赖顺序，测试脚本会很脆。改用逻辑外键 + 索引 + Service 层校验。

8. **为什么参数越界返回 400 而不是静默重置成 10？**
   → 静默改会让调用方以为生效了，也让自动化测试无法断言真实行为。

9. **`BlockAttackInnerInterceptor` 是干什么的？**
   → MyBatis-Plus 的防全表更新插件，不带 `WHERE` 的 `UPDATE`/`DELETE` 会直接抛异常。
