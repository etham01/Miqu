## 二、Miqu 项目 —— 补上「测试角色」一栏

**测试角色（独立完成）**
为项目构建「单元 / 接口双层」自动化测试体系，累计 **518 条用例**（JUnit 289 + pytest 229），覆盖 38 个接口。

- **分层测试设计**：JUnit + MockMvc 负责规则密集的分支覆盖（进程内运行、`@Transactional` 自动回滚）；pytest 打真实 HTTP + 真实 MySQL，负责端到端联调、序列化格式与接口契约验证。两者互补而非重复——MockMvc 快且能回滚，适合把业务规则钉死；pytest 慢但真实，能发现"单元测试全绿、联调就挂"的问题
- **用例幂等化改造**：针对 pytest 写入真实落库且无法回滚的问题，确立两条纪律——断言只取操作前后的**差值**、写数据只用**随机后缀的新建用户**；改造后整套用例可连续重复执行，无需中途重置数据库
- **专项覆盖**：并发场景（并发重复注册 / 关注 / 点赞下，最终恰好 1 行数据、计数只 +1；并发建会话收敛为同一条）；上传安全（按文件头魔数校验类型，改后缀的伪图片被拒，UUID 重命名防路径穿越）；11 个后台接口 × 3 种身份（未登录 / 非管理员 / 管理员）的 401 / 403 / 200 权限矩阵
- **缺陷沉淀为回归防线**：将开发中踩到的真实缺陷固化为用例——实体误标逻辑删除导致首次查询报表不存在、连接池懒初始化导致"健康检查通过但业务接口全部 500"（改为健康检查真实探测数据库）
- **覆盖诚实性**：对无法触达的分支（禁用管理员账号，因种子数据仅 1 个管理员）明确记录为覆盖缺口并给出补齐方案，不用恒真断言伪造覆盖率
