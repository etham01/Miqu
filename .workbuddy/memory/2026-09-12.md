### 必须记住的项目事实（本次实测）
- **Controller 16 个（controller/ 10 + controller/admin/ 6），Endpoint 恰好 50 个**
  （README 写的"38 个接口"是过时数字，漏算后台写接口等）
- **HTTP 恒 200**：`GlobalExceptionHandler` 无 `@ResponseStatus`，业务失败也是 200，只看 body 的 `code`
- 唯一例外：`GET /api/health` 在数据库挂时 `code=500`（HTTP 仍 200），且是唯一失败仍返回 data 的接口
- 错误码 50 个枚举，**`EMPTY_COMMENT` 从未被引用（死码）**；
  `INVALID_TARGET_TYPE` 有引用但 HTTP 层不可达（被 DTO `@Max(3)` 提前拦成 PARAM_INVALID）；
  405 不是枚举（handler 里硬编码 `Result.fail(405,...)`）
- **错误优先级**（此前悬而未决，本次由源码顺序确定）：
  `不能给自己(400) → 接收者/目标活跃(404/423) → 互关(403 NOT_MUTUAL_FOLLOW) → 内容校验(400)`
  ⇒ 非互关+接收者不存在 = **404**；非互关+空内容 = **403**（互关在校验链更前）
- `PUT /api/users/me` 的 Swagger 说"字段为 null 不修改"，但 `nickname` 是 `@NotBlank` **必填** → 契约误导
- `PUT /api/users/me/avatar` **不校验 `/uploads/` 前缀**（与动态图片校验不对称）
- pytest 实测覆盖：直接断言 44 / 间接 1（reports）/ 仅 JUnit 4（health、posts/{id}/likes、
  users/{id}/following、users/{id}/followers）/ **完全无覆盖 1（POST /api/files/image）**
- JUnit `AdminAccessControlTest` 覆盖 **11 个**后台接口但只有 4 个 `@Test`（内部循环）；
